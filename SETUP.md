# Local setup (macOS)

How to get Menya Kash building and running on a Mac, from a clean machine.
Written for Apple Silicon; Intel Macs work the same way.

There are two ways to run the app:

| Path | Time | What you get |
|---|---|---|
| **A. Chrome preview** | ~15 min | The full UI with fake seeded data. No SMS reading, no USSD, no app lock. Good for UI work. |
| **B. Android phone** | ~1 hour | The real app: inbox scan, live SMS, USSD dialing, app lock. Needed for demos and anything touching SMS/USSD. |

Do A first, then B.

---

## Prerequisites

- [Homebrew](https://brew.sh)
- Git
- Google Chrome (for path A)
- An Android phone with a USB cable (for path B)

## 1. Install Flutter (both paths)

```bash
brew install --cask flutter
flutter --version        # must be 3.44 or newer (pubspec.lock requires it)
```

## 2. Chrome preview (path A)

```bash
cd menyaKash
flutter pub get
flutter run -d chrome -t lib/main_web.dart
```

Chrome opens with a "web dev preview" banner and seeded fake transactions
(`lib/data/dev_seed_data.dart`); onboarding and app lock are skipped.
Press `r` in the terminal to hot-reload, `q` to quit.

## 3. Android setup (path B)

### 3.1 Install Android Studio

```bash
brew install --cask android-studio
```

Open it once and complete the setup wizard. It installs the Android SDK to
`~/Library/Android/sdk`.

### 3.2 Add the SDK command-line tools and accept licences

In Android Studio: **Settings → Languages & Frameworks → Android SDK → SDK Tools**,
tick **Android SDK Command-line Tools**, apply. Then:

```bash
flutter doctor --android-licenses     # answer y to everything
```

### 3.3 Use Android Studio's bundled Java

The build targets Java 17 (Gradle 9.1, AGP 9.0.1, Kotlin 2.3). A newer system
JDK (e.g. Java 25) can break the build, so point Flutter at the JDK that ships
with Android Studio:

```bash
flutter config --jdk-dir "/Applications/Android Studio.app/Contents/jbr/Contents/Home"
flutter doctor        # Android toolchain and Chrome should be ✓; Xcode/iOS can be ignored
```

### 3.4 Patch the `telephony` package (required)

`telephony` 0.2.0 (SMS read + live listener) is archived upstream and does not
compile on current Android tooling without edits. The file to edit lives in
your local pub cache, **not in this repo**, so every developer has to do this
on their own machine.

Run `flutter pub get` first, then open:

```
~/.pub-cache/hosted/pub.dev/telephony-0.2.0/android/build.gradle
```

and make these four changes inside the `android { … }` block:

```gradle
android {
    namespace 'com.shounakmulay.telephony'   // 1. add
    compileSdkVersion 36                      // 2. was 31
    compileOptions {                          // 3. add
        sourceCompatibility JavaVersion.VERSION_17
        targetCompatibility JavaVersion.VERSION_17
    }
    kotlinOptions {
        jvmTarget = "17"                      // 4. was "1.8"
    }
    ...
}
```

Background is in the comment in `android/build.gradle.kts`.
`flutter pub cache repair` (or a fresh package download) wipes these edits;
redo them if the `:telephony` build errors come back.

### 3.5 Prepare the phone

1. **Settings → About phone** → tap **Build number** 7 times to unlock Developer options.
2. **Settings → Developer options** → turn on **USB debugging**.
3. Plug the phone in and accept the "Allow USB debugging?" prompt.
4. Check that the Mac sees it:

```bash
flutter devices        # the phone should be listed
```

An emulator can run the onboarding screens, but it has no MoMo SMS and no SIM
for USSD, so use a real phone for anything SMS- or payment-related.

### 3.6 Run

```bash
flutter run            # first build takes 5–10 min while Gradle downloads
```

Go through onboarding, pick your providers and allow SMS access; the app then
scans the inbox.

> **Pay dials real USSD codes and moves real money.** When testing payments,
> send small amounts (e.g. 100 RWF) to your own second number.

## 4. Tests

```bash
flutter test           # unit tests; no device needed
```

## 5. After changing the database schema

`lib/data/database.g.dart` is generated by drift and committed. After any
change to the tables in `lib/data/database.dart`, bump `schemaVersion`, add a
backfilling `if (from < N)` migration step, then regenerate:

```bash
dart run build_runner build --delete-conflicting-outputs
```

## Troubleshooting

| Error | Fix |
|---|---|
| `Namespace not specified` or `jvmTarget` mismatch in `:telephony` | The patch in 3.4 is missing or was wiped. Redo it. |
| `Unsupported class file major version 69` | Gradle is running on Java 25. Redo 3.3. |
| `Your project's Gradle version (…) is lower than Flutter's minimum supported version` | Newer Flutter releases raise the Gradle floor. Bump `distributionUrl` in `android/gradle/wrapper/gradle-wrapper.properties` to the version the error names (currently 9.3.1). |
| `java.io.IOException: Premature EOF` during the first build | The Gradle download was cut off. Re-run; it resumes. |
| `flutter.sdk not set in local.properties` | Run `flutter pub get` once from the project folder. |
| Kotlin incremental-cache crash (`flutter_contacts`) | Already worked around in `android/gradle.properties`. Run `flutter clean` and retry. |
| Phone shows as "unauthorized" in `flutter devices` | Unplug and replug, then accept the prompt on the phone. |

## Privacy

Never commit real SMS exports, names or phone numbers. The `public/` folder
holding a device SMS export is gitignored for that reason. Redact before
sharing fixtures, tickets or screenshots.
